## goal prompt 骨架（每轮套用 templates/goal-prompt.tpl.md）

## 轮次与并行

- 主线轮（碰独占资源：{FILL: 如设备/生产环境/部署}）严格串行
- 支线轮（纯本地、文件域与主线不相交、spawn 时声明文件清单）可并行；commit 冲突主线优先
- 支线选题池：文档/手册、设计稿孵化、测试补强、工具精修——无可做选题则空转不硬造

## 收官判定（从严）

- 只信 git log + backlog 账本 + TaskOutput 三方一致；"任务查无+零产出"=疑似死（30 分钟无产出按存活疑犯处置并清查其子进程）
- agent 完成通知到达即接续，不等巡逻班次

## 失败保护

- 新 agent 30 分钟内失败且零 commit → 附原因重派一次；再失败停链记录
- 长任务命令必须带硬超时；agent 异常终结时巡逻清查孤儿进程

## 环境守卫（{FILL: 按项目写，无则删除本节}）

示例（实录）：环境值双模式（用户睡眠时切换到低影响档，巡逻用探测命令核对并调回漂移；**模式切换时必须通知在跑 agent——它们不会重读 state**）；独占资源单例守恒（启动长任务前查残留+登记 pid+重启必杀旧）。

## 用户拍板节

需用户决策的事项一律记 backlog"用户在场"节并继续其他工作，不阻塞循环。常见：部署生产/删数据/方向取舍/阈值确认。

## 负责人复盘制度

每 3 轮主线收官后更新 leadbook.md：轮次台账一行式 + 系统级经验（按杠杆排序）+ 待改进核销。事故后立即固化对策进本协议。
